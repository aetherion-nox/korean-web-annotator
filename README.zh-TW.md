# 韓語網頁標註器

[简体中文](README.md) · **繁體中文** · [English](README.en.md) · [日本語](README.ja.md) · [한국어](README.ko.md)

在韓語網頁中顯示漢字詞與外來語的詞源標註，支援整頁、選取範圍，以及選用的大型語言模型審核。基本標註在瀏覽器內完成，不需要 API Key 或本機伺服器。

## 1. 安裝擴充功能

1. 前往 [GitHub Releases](https://github.com/aetherion-nox/korean-web-annotator/releases/latest)，下載附件 **`Korean-Web-Annotator-v*.zip`**（完整安裝包），不要下載 GitHub 自動提供的 **Source code** ZIP。
2. 解壓縮。在 Chrome 開啟 `chrome://extensions`，啟用**開發人員模式**，點選**載入未封裝項目**，選擇含有 `manifest.json` 的資料夾。
3. 手機可使用支援載入擴充功能的瀏覽器（例如 Quetta）匯入解壓縮的擴充功能。

更新後，請重新載入擴充功能並重新整理已開啟的網頁。通常不需要重新匯入詞典。

> **從原始碼安裝：** 若使用 **Code → Download ZIP**，需安裝 Python 3.10+，並在解壓縮的目錄先執行 `python restore_distribution.py`，還原未納入原始碼儲存庫的大型執行環境檔案。Release 附件不需要此步驟。

## 2. 匯入詞典

1. 從[韓國國立國語院韓國語基礎詞典下載頁](https://krdict.korean.go.kr/download/downloadPopup)下載 **JSON 格式的詞典 ZIP**。
2. 開啟擴充功能的**引擎 / API 設定**，選取 ZIP 檔案並執行匯入。**不需要事先解壓縮詞典。**

如果手機匯入較慢，可先在電腦上轉換成 SQLite：

```sh
python python/backend/upstream/scripts/import_dictionary.py "詞典.zip"
```

將產生的 `python/backend/upstream/hanja_dict.db` 傳到手機，再於同一個設定頁面匯入。

## 3. 標註與複製

1. 開啟含有韓文的網頁，點選擴充功能圖示，依需要啟用**漢字詞**及**外來語**標註模式。
2. 點選**一鍵標註整頁**；也可選取文字後使用**標註所選文字**、網頁工具列或右鍵選單。
3. 使用**撤銷上次標註**或**還原全部**回復網頁顯示。工具列隱藏時，可點選可拖曳的懸浮球重新開啟。
4. 在**選取與複製文字時**設定複製內容：目前正文、正文加標註、**僅原始韓語（預設）**，或僅上方標註。

若動態網頁重新繪製後需要恢復已完成的標註，請保持**動態網頁相容：恢復已有標註**開啟。

## 4. 選用：大型語言模型審核

基本標註只需要詞典。若想用模型處理歧義，請開啟**引擎 / API 設定**，選擇服務商、模型與介面，填入 API Key，測試連線並儲存，接著啟用**選用模型審核**。

- **一般審核：** 將本機規則無法確定的候選交由模型判別。可自行啟用**全部交由模型審核**；呼叫次數和費用可能增加。
- **模型重審選取範圍：** 選取文字後點選對應按鈕，要求模型重新判斷該範圍；需設定 API，但可不開啟一般審核開關。
- **手動聊天審核：** 在設定中啟用後，複製或下載面板產生的提示詞，傳給聊天模型，再將完整 JSON 答案貼上或匯入面板，驗證並套用目前批次。**不需要 API Key**，但仍需詞典。
- 大型任務可在設定中調整每批上下文容量；若希望分批顯示結果，請開啟**邊完成邊標註**。

**實驗：模型補充詞源與重新斷詞：** 漢字詞、外來語原詞及重新斷詞可分別啟用（預設關閉）。重新斷詞允許模型從韓文原文重辨完整詞邊界，修正 Kiwi 漏詞或誤拆；必須啟用模型審核及至少一種詞源補充。漢字數量必須符合韓文音節數，人名保護仍生效。依上下文容量自動分批，不再採用固定 120／12 筆上限，請留意費用及誤判。

**預設審核設定與單音節保護：** 全新安裝預設開啟模型審核、預先載入、姓名保護、模型補充漢字詞及外來語原詞、重新斷詞和手動聊天審核；預設關閉品詞篩選與全部候選審核。新增「單音節諺文詞禁止本機標註」預設開啟：單個韓文字音節不在本機自動轉換，可送模型審核，無有效答案則保留原文。已儲存的設定不會被強制覆蓋。

**v1.1.61 風險複核：** 「唯一候選風險複核」與「單音節諺文詞禁止本機標註」預設開啟。詞典中完整且可靠對齊的混種詞（如 팀장 → team長）可照常本機標註；Kiwi 錯拆而沒有完整詞條的複合詞先暫緩局部轉換。缺乏上下文證據的短詞唯一候選也交給模型，重疊的重新斷詞與詞義審核合併一次；無有效答覆便保留韓文。

**v1.1.62 詞邊界保護：** 連續諺文內沒有確定邊界的子詞不再直接用詞典自動轉換；模型若選擇不可靠的局部候選，安全降級為 KEEP。只將有分詞風險的片段交模型重新斷詞，單批最多 64 個判斷目標，但完整文本仍分批處理。

**v1.1.63 大上下文分批修正：** 取消每批64筆的固定限制。512K／1M會在輸入、JSON答案及安全餘量容許時保留單批；API配置可設定最大輸出tokens（預設16384），手動聊天可設定回覆限制（預設65536）。上下文與輸出上限需分別符合模型實際能力。

**v1.1.64 未收錄詞復原：** 啟用模型重新斷詞與相應詞源補充後，沒有完整詞條甚至沒有局部詞條的名詞複合語也能以完整詞段送審；模型可利用已知詞素、上下文和語音對應提出原文詞源。機構術語、縮寫詞不依賴固定詞表。明確受保護的人名仍不准猜造，所有結果須嚴格檢查原文字位與字符數。

**v1.1.65 逐條修復：** GEN_SEGMENTS 在原文詞段位置唯一時可自動校正 start/end；單音節詞源須有實際字典候選與獨立詞性及助詞證據。手動聊天審核若僅少數目標失效，保留已通過結果並產生只含無效 target_id 的修復提示，回填相同 batch_id 的少量答案即可續行。

**v1.1.66 手動批次驗證修復：** 背景與網頁離線復原共用驗證器；錯誤可辨識具體 target_id、原因，保留已通過的答案，僅重交未通過的目標。自動剔除無改變的生成片段；符合詞典、定語或助詞證據的一音節詞素可以通過。網頁導覽的獨立連結間會保留邏輯文字分界。

使用 API 審核時，相關網頁文字和候選會送至你設定的模型服務商；請留意隱私與費用。

**v1.1.67 混合錯誤批次修補：** 自動與手動模型審核不再因其他批次 ID 而捨棄合法答案；重複的 target_id 只影響該目標。局部修復提示詞以實際待修復 ID 建立 JSON 範例，不再固定使用 t0；batch_id 不符仍拒絕整批。

**v1.1.68 手動審核即時預覽：** 模型生成詞源不再強制輸出 confidence 或 evidence，只需 replacement／segments；詞典選項仍須使用合法 choice_id。有效答案立即以可回復的預覽顯示，失敗的 ID 繼續修復；新增轉換、保留原文與網頁位置失效診斷。預覽不代表整批已完成。

**v1.1.69 唯一候選語義風險修正：** 單一詞典候選即使分數很高，若缺乏可靠搭配或單位證據，兩音節詞仍送模型查核釋義；不會將相同讀音的錯誤義項直接寫入網頁。多詞典記錄及有完整搭配依據者保留快速路徑；關閉模型審核時則保留來源文字。

**v1.1.70 完整詞幹優先與定向修正：** 生成漢字片段前先判定完整詞幹及助詞、固有詞邊界。孤立單音節仍受保護，但重試會收到針對原目標的校驗原因，重新判斷完整詞而非硬湊漢字；手動修正提示詞附 `repair_feedback`，自動重試只要求失敗 ID。輸出預算不再包含 confidence/evidence。

**v1.1.71 安全回退與實際標註審計：** 合併整詞時保留舊詞典候選，整詞 KEEP 或無效時再審查；只有可靠獨立詞界可重審子詞，否則繼續審核整詞，不自動套用同音漢字。新增模型決定與實際 DOM 標註分開統計，包含 KEEP、非轉換、跨節點失敗與頁面變動原因。修正 GEN_SEGMENTS 快取的多餘欄位，唯一子詞可省略兩個座標欄位。補審可能增加模型請求。

## 5. 排除問題

- **按下標註沒有反應：** 確認詞典已匯入、擴充功能已重新載入，再重新整理網頁。
- **更新後仍有舊錯誤：** 在 `chrome://extensions` 重新載入擴充功能，再重新整理原網頁。
- **手動審核批次未完成：** 保持目前網頁開啟，逐批提交並驗證 JSON；完成前不要重新整理頁面。
