在韩语网页中显示汉字词和外来语的词源标注，支持整页、选区和可选的大模型审核。基础标注在浏览器内完成，无需 API Key 或本地服务器。

## 1. 安装扩展

1. 打开 [GitHub Releases](https://github.com/aetherion-nox/korean-web-annotator/releases/latest)，下载附件 **`Korean-Web-Annotator-v*.zip`**（完整安装包），不要下载 GitHub 自动提供的 **Source code** ZIP。
2. 解压文件。在 Chrome 中打开 `chrome://extensions`，开启**开发者模式**，点击**加载已解压的扩展程序**，选择包含 `manifest.json` 的文件夹。
3. 手机端可使用支持扩展加载的浏览器（例如 Quetta）导入解压后的扩展。

更新扩展后，重新加载扩展并刷新已打开的网页。一般不需要重新导入词典。

> **v1.1.56.2 网站访问修复：** 为了允许网页工具条、整页标注及跨域 iframe 正常工作，插件会请求 **HTTP/HTTPS 网站访问权限**（浏览器可能提示“读取和更改您在所有网站上的数据”）。如访问仍被浏览器限制，请在 `chrome://extensions` → 本扩展 → **详情** → **网站访问权限** 中允许当前网站或所有网站，然后刷新目标页面。此权限让标注器在网页中读取要标注的文本；**不代表自动向模型发送文本**，只有在开启相应 API 审核时才会发送到所配置的模型服务。浏览器内部页面 `chrome://`、扩展管理页、Chrome 商店等受保护页面无法注入，无论是否授权。

> **从源码安装：** 如果使用 **Code → Download ZIP**，需要 Python 3.10+，在解压目录先执行 `python restore_distribution.py` 以恢复未放入源码仓库的大型运行时文件；Release 附件无需此步骤。

## 2. 导入词典（可选）

1. 在[韩国国立国语院韩国语基础词典下载页](https://krdict.korean.go.kr/download/downloadPopup)下载 **JSON 格式的词典 ZIP**。
2. 打开扩展的**引擎 / API 设置**，在词典导入区选择 ZIP 文件并执行导入。**不需要先解压词典。**

如果手机导入较慢，可以先在电脑上把词典转成 SQLite：

```sh
python python/backend/upstream/scripts/import_dictionary.py "词典.zip"
```

将生成的 `python/backend/upstream/hanja_dict.db` 传到手机，再从相同设置页导入。

## 3. 标注和复制

1. 打开含有韩文的网页，点击扩展图标，按需要开启**汉字词**和**外来语**标注模式。
2. 点击**一键标注整页**；也可以选中文字后使用**标注所选文字**、网页工具条或右键菜单。
3. 使用 **撤销一步／重做一步** 在当前标签页的标注操作历史中前后移动（显示可撤销、可重做步数）；**清除全部标注**是独立的显式清理操作，会重置本页历史。工具条隐藏后，可点击可拖动的悬浮球重新打开。
4. 在**选择与复制文字时**设置复制内容：当前正文、正文加标注、**仅原韩语（默认）**或仅上方标注。

> **v1.1.56.7 提示词操作后自动定位答案框：** 点击手动审核面板中的“复制提示词”或“下载提示词 TXT”后，若面板在小屏幕出现内部滚动条，会平滑滚动到下方的 JSON 答案输入框。仅滚动插件面板，不滚动网页正文，也不自动聚焦输入框弹出手机键盘；面板无需滚动时保持原位。原有复制失败提示、下载操作、答案自动应用与多批次行为不变。

动态网页重绘后需要重新显示已完成的标注时，保持**动态网页兼容：恢复已有标注**开启。

> **v1.1.56.8 动态评论区标注恢复：** 修复“边完成边标注”预览已显示汉字、正式审核通过后视觉内容没有变化，却未把最终标注写入动态恢复缓存的问题。此前评论区、推荐卡片等 React 重绘后可能瞬间丢失标注，即使“恢复已有标注”已经开启。现在正式确认时补记来源精确的恢复记录，后续网站重新渲染相同文本会恢复原有汉字／外来语标注；未确认的临时标注不会被当作永久结果。此恢复不需要新一次模型调用，也不受“整页标注完成后停止持续监测”开关影响。若站点真的改变评论原文、位置无法安全匹配，仍不强行替换。

> **v1.1.56.16 专名词源按文字系统分别审核：** 在开启实验性外来语补全且使用外来语标注时，允许有可靠身份依据的品牌、机构及外国人名使用已知拉丁字母原名；未被普通词典候选覆盖的完整专名可进入独立的 KEEP/LLM 审核，但不会因此触发本地自动转换。实验性汉字补全允许非人名专名，但继续阻止对人名／疑似人名自由猜测汉字。真正的 JSON `null` 始终保留原文，词界不完整或跨空格的目标不能自由填写。手动断线补录现在也按汉字／拉丁字分别保存许可，以免出现后台和页面恢复校验不一致。提示词采用通用规则，不写死专名案例；其余配置及算法保持原样。

> **v1.1.56.15 禁止跨空格构建词源审核目标：** 原文中的独立词不再因为去掉空格后恰好命中词典，就被拼成 `부 등`、`황 전`、`급 환` 这样的待审核目标；混合词／复合词查词入口现在仅生成同一个原文连续词界内的目标。**词典查询别名仍保持原有空格、`^`、连字符的精确索引检索**（例如原文 `이산화탄소` 仍可检索词条 `이산화^탄소` 或 `이산화 탄소`），不改动词典内容、已有词选项格式、Kiwi 分词及手动/API 审核机制。真正含空格的原文词组不再作为一个跨空格目标提交模型；原文各词仍可独立标注。人名／专名实验性自由填写限制本版不变，后续可单独评估放宽策略。

> **v1.1.56.13 跨框架审核错误定位：** 修复后台断线后，跨框架离线手动审核的只读预校验仅报告“尚有 N 个目标无法与当前原文安全对应或选择无效”，却隐藏已有的具体目标 ID、原始韩文、句子/位置与校验失败原因。现在会显示 `t42「원잠」［p3:2-4］：无效 c：...` 或 `未提交有效结果`、`重复 target_id`、`原文结构无法安全对应` 等对应信息，最多列出 8 个，并将 `frame 0` 明确显示为主页面；同时消除错误提示偶发重复句号。JSON t/c 协议、安全校验条件、跨框架全体先校验再提交（不提前部分写入）和原有词典、模型、动态页面算法均不改变。**该修复解决错误定位信息缺失，但不能单凭原始笼统报错断定模型答错还是网页发生变化。**

> **v1.1.56.12 整页启动加速：** 原来的跨框架整页标注总是等待固定的 4.8 秒，即使完全没有子框架。现在改为自适应收集：没有子框架时在检测后采用约 350 毫秒静默期；已发现子框架时使用约 850 毫秒静默期，且必须先完成各框架的扫描与登记；新的子框架导航会延长静默期，最长不超过原来的 4.8 秒收集上限。统一审核仍然只生成一个跨框架批次，空白主框架仍可承载子框架的手动审核；如果无法读取框架清单，会保留原等待上限以确保安全。分析完成后的动态评论补扫、手动审核、撤销重做和真实词典/分词器初始化提示均保持不变。特殊情况下，首次静默期结束后才出现的 iframe 仍可能需要再次手动标注或启用后续动态监测。

> **v1.1.56.11 词典初始化进度提示修复：** 每轮新标注开始时显示“准备分析…”，不再直接显示“加载词典…”。移除分析管线自行发送的虚假 `dictionary` 进度；仅当浏览器后台引擎确实需要恢复数据库、初始化 Python 词典运行环境时，才显示“加载词典…”，Kiwi 需要真正初始化时仍显示“初始化分词器…”。正常连续标注复用已驻留的 offscreen 引擎、Worker、词典和 Kiwi，仍会进行轻量引擎状态校验，但不会因此重新加载整份数据库。此版只调整进度信号与界面提示，不更改分析、审核、缓存、跨框架或动态页面算法。浏览器回收引擎页后确实可能需要重新初始化。

> **v1.1.56.9 多级撤销与重做：** 像 Word 一样按**逻辑操作**记录历史：整页标注、选区标注、模型复审、手动审核及自动增量标注每轮各是一历史步；多 iframe 同一轮按一步计数，避免不同框架重复累加。连续标注 A、B、C 可以逐次撤销到 A，随后逐次重做回 C；撤销后产生新的实际标注 D 会丢弃旧的 B/C 重做分支。保留以前的汉字标注及动态页面恢复快照，不重新调用模型。弹窗与页面工具条新增“重做”及步数状态；“清除全部标注”与重做分离，执行后会重置撤销与重做历史。仅作用于当前标签页存活的 DOM，网站自身重绘、导航离开或不可访问的 iframe 不会被强制覆盖。为避免抢占网页自己的编辑快捷键，本版不全局拦截 Ctrl+Z/Ctrl+Y，使用插件按钮执行。

> **v1.1.56.5 撤销／还原修复：** 撤销针对的是**最近一次实际修改过网页标注的操作**。例如：原有汉字标注被新的模型结果替换，撤销会恢复修改前的旧汉字标注，而不是一律退回无标注韩文；重新分析但没有产生新审核或新标注时，不会清除旧标注或创建虚假的修改记录。无论标注来自整页、选区、模型重审、手动审核还是自动标注，都共用这套历史。整页跨框架的一次标注作为一个操作，点击一次撤销会在仍可访问且历史匹配的框架中一起撤销；不会误撤销其他框架较早的选区标注。**还原全部**清除本标签页主页面及仍可访问的 iframe 与开放式 Shadow DOM 中的插件标注；已经导航离开的旧 iframe 不会被强行修改。恢复旧结果始终检查实际 DOM 是否仍为原文，不会覆盖网站自己更新后的内容。

### v1.1.56.1 审核答案格式（不兼容旧版）

新版统一使用精简的 `t`（目标 ID）与 `c`（选择项／词源）。例如：

```json
{"batch_id":"abc123","results":[{"t":"t0","c":"c0"},{"t":"t1","c":null},{"t":"t2","c":"韓國"},{"t":"t3","c":"game"}]}
```

`c:null` 是真正的 JSON null，表示保留原韩文；`"null"` 字符串与它不同。字典候选仍使用该目标对应的 c/n 选项键；实验性直接补全可写入真实汉字或拉丁字母原词。单独的字符串不再被当作保留标记，因此真实的借词来源 `"KEEP"` 也可以参与普通词源校验。手动审核必须原样带上本批 `batch_id`，每个结果的 `t` 必须唯一且属于该批次。智能分词修复启用时，可另外包含独立格式的 `repairs` 数据；不启用时请只提交 `batch_id` 和 `results`。

**旧版 `results` 的 `target_id/choice_id` 字段和上一个实验性的纯位置数组答案均不再接受。** 更新扩展后请重新生成新的提示词，不能直接回填旧批次结果。

> **v1.1.56.3 手动审核修复：** 正在等待手动答案时，普通子 iframe 的动态加载/断开不会再取消整个跨框架批次；已通过校验的答案会先写入当前任务的备份，再处理结束信号。**只有全部手动批次成功应用后才自动收起输入框**，而且提示词及 JSON 答案仍保留，可重新打开查看或复制。手动点击「收起」不会取消审核。若主网页本身已导航或扩展整体重载，旧的跨框架定位仍会安全失效，不能在新网页上强行应用旧位置。

## 无词典模式的词源审查与读音校验

- **汉字词源读音校验默认开启**（引擎 / API 设置中可独立关闭）。开启时检查已知多音字和词首音变；关闭只跳过模型汉字与韩文的读音比较，不关闭字形、词界、位置或姓名保护。
- 现有汉字读音表尚不完备，默认开启仍可能有合法词源被误拒；关闭后也可能接受错读的汉字。模型词源始终标记为“未经词典核实”。
- 无词典模式不再盲目合并相邻普通名词；明确标记的 XSN/XSM 派生后缀可以跟随词干。模型填写可靠的汉字词干时，后缀仍显示为韩文。
- 分词修复的 add 必须指定空 old_target_ids，replace 应指定已有目标。空 ID 的 replace 仅在不与任何已有目标、姓名、标注或选择范围冲突时，才规范化为 add。
- 日志现在区分直接词源拒绝原因；网页完成时报告审核数、KEEP、有效直接词源、投射标注和当前连接的 DOM 标注数。

## 有词典 + 实验性词源补全：独立判断优先

开启实验性汉字词源或外来语词源补全时，模型先依据韩语原文和上下文独立判断词义、词界和可靠词源，再核对词典现有候选。真实匹配的词典义项继续优先使用其 c/n 选项键；词典全部不匹配但模型可靠地知道词源时，可在同一轮 results[].choice_id 直接填写对应的汉字或拉丁字原词；不确定时 KEEP，不得捏造词源。

仅实验性模式采用 choice_id_mode: open-origin（字典与直填均适用），并标明词典候选不是封闭选择集。普通有词典模式维持现有候选和提示词，不会启用模型直填词源。新增内容不改变已有词典校验、汉字读音校验开关、专名保护和 DOM 写入。

## LLM 智能分词修复：原 target 自动作废规则（实验性）

仅开启「LLM 智能分词修复」时使用：模型先提交 `repairs`，成功验证的 `replace/delete` 所引用的原始 target 在本批视为已替代，`results` 可以不再填写它们。未被替代的原始目标仍需逐个填写；仅作为全文扫描占位符的 `scan_only` 也无需再专门返回 KEEP。

`add` 只能新增真正要标注的汉字或拉丁字词源；不要为固有词或不需要转换的原文生成 KEEP 修复。`replace` 只需覆盖要标注的正确片段，原词其余韩文字母自动保留，不再需要 KEEP 碎片。`delete` 可省略 `choice_id`，旧式 `choice_id: KEEP` 仍被接受。

词界、源文偏移、选区、人名保护、重叠和读音验证仍然启用。**修复失败不会撤销旧 target**：有有效旧结果则保留，没有则要求补交。手动审核及断线页面恢复使用同一套修复校验规则；已安全接受的部分不会因后续冲突答案而被撤销。该功能不改变未开启实验性分词修复时的普通词典审核协议。

## 动态新闻网页整页扫描修复（实验分支）

- 整页分析不再按前 3000 个韩文文本节点截断；完整 DOM 文本节点统一收集后，依现有分词、段落和 LLM 批次预算继续分批分析。原有恢复标注缓存采用独立上限，不会截断正文扫描。
- 自动增量分析按 **具体 DOM 节点与文本版本** 去重，而不再按韩文字符串去重。同一新闻标题出现在文章正文、侧栏和排行榜时各自独立处理。
- 排除确实隐藏的元素（如 `display:none`、`hidden`、`aria-hidden=true`），但不排除仅位于屏幕外的内容。打开标签后可重新发现刚显示的韩文。
- 完整扫描可遍历开放式 Shadow DOM（含嵌套开放式根）；持续自动标注打开时也监听其中已发现的根及普通页面 `class/style/hidden/aria-hidden/inert/open` 属性变化。浏览器不能访问关闭式 Shadow DOM；跨源 iframe 仍依赖独立内容脚本和网站权限。
- 默认保持「整页完成后停止自动标注」开关的语义：手动和 API 模式在整页完成后均停止新一轮自动分析（不再额外进行 15 秒补扫）。若需要滚动加载后长期自动标注，主动关闭该开关以启用原有持续监测。
- 日志现在区分检测到的文本节点、含韩文节点、隐藏/已处理跳过数、实际提交的 DOM 节点、Kiwi 本地候选数、模型接收数与最终 DOM 标注数。仅凭一个标题未出现在模型提示词里，不能再直接推断它未被 DOM 扫描。

## 整页标注：跨 iframe 框架检测与安全分发

点击「整页标注」（或在主框架使用右键整页标注）时，首先保留原来的主框架扫描流程，随后使用 Chrome 的 `webNavigation.getAllFrames` 枚举现有子框架。每个可访问的子框架先执行**只读韩文可见性探测**：没有可见韩文、隐藏、尺寸太小的广告/追踪框架不会启动 Kiwi 或模型；含有可见韩文的 iframe 则在自己的 DOM 中独立标注。子框架的失败、无权限和无内容不会阻断主文章。

为了兼容动态插入的 iframe，用户主动点击整页标注后，在**最长 15 秒的有界窗口**内对新载入的框架进行补扫（并在第 1.7 秒、第 4.8 秒检查一次）。按文档标识去重，避免多个异步事件重复发送模型请求。窗口结束后不再自动启动新的 iframe，保留「整页完成后停止自动标注」开关的语义。

`manifest.json` 加入 `webNavigation` 用于枚举网页中的框架；`match_origin_as_fallback` 支持部分同源创建的 `about:`、`blob:`、`data:` 框架。**不会自动申请所有第三方网站权限**；用户未授权或 Chrome 禁止脚本注入的跨源 iframe 会在主框架诊断日志显示「无法访问」，并由 Chrome 自身权限规则保护。可在扩展程序的网站访问设置中按需允许相应域名。独立 iframe 的手动模型审核仍然使用其自身内容区域，不会自动合并到主页面的手动审核弹窗。

朝鲜日报所列的 `오늘의 인기정보` 和 `많이 본 정보` 并未出现在此前从 CI 下载的原始 HTML 或无头浏览器主框架中；是否在用户实际浏览器的第三方嵌入内容里，仍需该浏览器的现场 DOM 复核，不能保证多框架修复必然覆盖这两个标题。

## 多 iframe：统一批次审核（手动和 API 一致）

整页标注从每个可访问框架收集待标注句子，将句子 ID 加上内部框架前缀，然后由后台执行**一套共享的本地分析、候选池、批次预算和 LLM 审核**。各框架原文及位置独立保存，结果按来源映射回正确的 iframe。共享批次 JSON 只有一份，不会因多个 iframe 而重复发送相同的系统提示词和候选定义。

- **手动模式**：只在顶层网页打开一个审核窗口，批次包括正文及参与的 iframe。即使顶层网页没有待审核词，也可承载窗口。补交及下一批继续使用同一窗口。
- **API 模式**：各框架词条参加同一批次预算。只有超过用户选定的上下文/输出上限时，才按原有策略分批，而非每个 iframe 强制单独请求。
- **上下文**：每个框架的原文附带独立分界，保留原始来源与 UTF-16 词位，不把侧栏与正文误当成连续一句话。
- **动态 iframe**：点击整页后约 4.8 秒内收集新增框架并合并；超过收集期才出现的 iframe 不会另外创建一套手动/API 批次，可以待页面加载完再次执行整页。
- **安全约束**：模型结果通过后台验证后，发回原框架写入。框架断线时取消本轮合并任务，避免错误映射。跨框架合并手动批次暂不支持后台完全断线后在主页面直接应用其他跨源框架的答案；提示词和已粘贴文本仍可保存后重新审核。单页面、选区等原有断线恢复保留。

webNavigation 只识别已存在的 iframe；访问受限的第三方框架会被跳过并计入日志，不会绕过 Chrome 的站点权限。

## 主页面唯一工具条（修复 iframe 重复悬浮工具）

跨框架标注过程中，内容脚本仍在每个可访问 iframe 内运行，以分别扫描、写入和恢复其 DOM 标注；但 **`.kra-mobile-selection-bar` 工具条、悬浮球和对应的韩文可见性工具监听只在最外层主文档创建**。子框架的进度消息不会创建工具条，完成标注后也不会出现子框架残留工具。主文档本身没有韩文但存在子框架内容时，合并审核主框架仍可显示主工具条。

主工具条的「标注整页」按钮现在与弹窗及右键整页操作走同一套跨框架合并审核管线，手动与 API 均合并模型批次，不会因按钮入口不同退回单框架分析。子框架中通过独立选区或右键直接请求的单框架手动审核仍可显示其专用的审核面板，但不会额外生成工具条。

升级扩展后建议刷新已打开的目标网页，使旧版内容脚本以及旧框架工具条不再运行。
