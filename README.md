# 韩语网页标注器

**简体中文** · [繁體中文](README.zh-TW.md) · [English](README.en.md) · [日本語](README.ja.md) · [한국어](README.ko.md)

在韩语网页中显示汉字词和外来语的词源标注，支持整页、选区和可选的大模型审核。基础标注在浏览器内完成，无需 API Key 或本地服务器。

## 1. 安装扩展

1. 打开 [GitHub Releases](https://github.com/aetherion-nox/korean-web-annotator/releases/latest)，下载附件 **`Korean-Web-Annotator-v*.zip`**（完整安装包），不要下载 GitHub 自动提供的 **Source code** ZIP。
2. 解压文件。在 Chrome 中打开 `chrome://extensions`，开启**开发者模式**，点击**加载已解压的扩展程序**，选择包含 `manifest.json` 的文件夹。
3. 手机端可使用支持扩展加载的浏览器（例如 Quetta）导入解压后的扩展。

更新扩展后，重新加载扩展并刷新已打开的网页。一般不需要重新导入词典。

> **从源码安装：** 如果使用 **Code → Download ZIP**，需要 Python 3.10+，在解压目录先执行 `python restore_distribution.py` 以恢复未放入源码仓库的大型运行时文件；Release 附件无需此步骤。

## 2. 导入词典

1. 在[韩国国立国语院韩国语基础词典下载页](https://krdict.korean.go.kr/download/downloadPopup)下载 **JSON 格式的词典 ZIP**。
2. 打开扩展的**引擎 / API 设置**，在词典导入区选择 ZIP 文件并执行导入。**不需要先解压词典。**

如果手机导入较慢，可以先在电脑上把词典转成 SQLite：

```sh
python python/backend/upstream/scripts/import_dictionary.py "词典.zip"
```

将生成的 `python/backend/upstream/hanja_dict.db` 传到手机，再从相同设置页导入。

## 3. 标注和复制

1. 打开含有韩文的网页，点击扩展图标，按需要开启**汉字词**和**外来语**标注模式。
2. 点击**一键标注整页**；也可以选中文字后使用**标注所选文字**、网页工具条或右键菜单。
3. 使用**撤销上次标注**或**还原全部**恢复网页显示。工具条隐藏后，可点击可拖动的悬浮球重新打开。
4. 在**选择与复制文字时**设置复制内容：当前正文、正文加标注、**仅原韩语（默认）**或仅上方标注。

动态网页重绘后需要重新显示已完成的标注时，保持**动态网页兼容：恢复已有标注**开启。

## 4. 可选：大模型审核

基础标注只需要词典。若要用模型处理歧义，打开**引擎 / API 设置**，选择服务商、模型及接口，填写 API Key，测试连接并保存，然后开启**启用可选模型审核**。

- **普通审核：** 本地规则无法确定的候选交给模型判别。可以按需开启**全部交给大模型审核**；请求次数及费用可能增加。
- **模型重审选区：** 选中文字后点击对应按钮，要求模型重新判断该选区；需要 API 配置，但普通审核总开关可以关闭。
- **手动聊天审核：** 在设置中开启后，复制或下载面板生成的提示词，发送给聊天模型，再将完整 JSON 答案粘贴或导入面板，校验并应用当前批次。**不需要 API Key**，但仍然需要词典。
- 大任务可以在设置中选择每批上下文容量；需要逐批显示结果时开启**边完成边标注**。

**实验：模型补充词源与重新分词：** 可分别开启汉字词、外来语原词及重新分词开关（新安装默认开启）。重新分词允许模型从韩语原文重新识别完整词边界，即使 Kiwi 漏词或拆错也能补审；必须同时开启模型审核及至少一种词源补充。汉字与韩文字音节数量必须一致，姓名保护照常生效。词段按设置的上下文容量自动分批，不设固定 120／12 个上限；请留意 API 费用与生成错误。

**默认审核设置与单音节保护：** 新安装默认开启可选模型审核、浏览器预加载、姓名保护、模型补充汉字词及外来语原词、模型重新分词和手动聊天审核；默认关闭词性过滤和全部候选审核。新开关「单音节谚文词禁止本地标注」默认开启：单个韩文字音节不会由本地自动换成汉字或外语原词，已有候选仍可交给模型，无有效回复则保留韩文。已经保存的设置不被更新强制覆盖。

**v1.1.61 风险复核：** 默认开启「唯一候选风险复核」和「单音节谚文词禁止本地标注」。完整词典收录且能唯一可靠对齐的混种词（如 팀장 → team長）仍可本地标注；词典没有完整词条、Kiwi 又拆出单音节成分的可疑复合词会先暂缓局部转换。缺少上下文证据的短词唯一候选也会交模型审核。模型重新分词与词典义项同范围时合并一次审查；无有效结果则保留原文。此功能不能保证识别所有漏收同音词。

**v1.1.62 词边界与审核安全：** 本地词典不能仅因匹配某个内部音节就转换完整词。连续谚文中未被确认的子词段先暂缓；模型审核即使返回某个错误的局部选项也会保守保留原文。重新分词集中处理真正有边界风险的词段，避免把无风险的菜单项和活用词全部重复送审。每个模型批次最多 64 个决策，所有目标仍会逐批处理。修复参考：문진가두／問津歌、자광각／各、참답게／斬、북경C／향gin。

**v1.1.63 大上下文分批修复：** 已撤回每批 64 个判断目标上限。512K／1M 档位将尽量一次审核全部目标，只有预计输入 + JSON 答案 + 安全余量超出上下文，或答案超出实际输出限制，才拆成多个批次。可在 API 模型档案设置「最大输出 tokens」（默认 16384），在浏览器引擎设置「手动聊天单批最大回复 tokens」（默认 65536）；两者独立于上下文容量，须按服务商／聊天模型实际支持情况填写。

**v1.1.64 未收录词恢复：** 在「模型重新分词」及对应词源补充开启时，词典缺少完整复合词甚至缺少所有子词条，也可利用 Kiwi 的词汇边界线索形成完整词段审核任务。模型可结合可信子词典证据、原文和语境恢复原始汉字或外来语词形；名词性机构术语、缩略语等不必依赖预设词表。已确认的人名继续保护，完全无把握时保留韩文；所有生成结果仍需位置、字音数量与字符校验。新增审核可能增加费用。

**v1.1.65 手动审核纠错：** 模型的 GEN_SEGMENTS 子词若在当前目标原文中唯一出现，可自动规范化错误 start/end（如四音节外来语被错数成五音节）。孤立单音节词源只有同时满足词典候选、Kiwi 独立词性与周围语法边界时才获准；名字仍防止纯音近猜造。手动聊天提交中某些 ID 无效时，扩展保存其余有效答案并显示仅含待修复 ID 的新提示词；再次贴回相同 batch_id 的少量修复 JSON 即可完成本批，无需重新生成全部答案。

**v1.1.66 手动审核校验统一：** 后台与网页断线恢复现在共用同一个生成词源校验器，错误时明确给出 target_id、错误类型与原因，合法行逐条保存。手动审核若有少数无效项，可沿用本批 batch_id，只为剩余 ID 生成修复提示词并补交；网页连接断开也能继续。无效果的「韩文→同样韩文」GEN_SEGMENTS 片段会安全忽略；有词典及定语／助词词性证据的单音节能获得许可。点击链接之间没有空格的导航文字不会再轻易被拼成一个词。升级扩展后应刷新网页并重新开始批次。

使用 API 审核时，相关网页文本和候选会发送给你配置的模型服务商；请留意隐私与费用。

**v1.1.67 混合错误批次补丁：** 自动与手动模型审核不再因为回复包含跨批 ID 而舍弃其他有效结果；重复的 target_id 只影响该目标，合法答案保持已保存状态，剩余 ID 可逐条补交。纠错提示词的 JSON 示例改用当前实际待修复 ID，不再固定写 t0，且错误消息最多显示前三种具体问题。batch_id 不匹配仍拒绝整份回复。

**v1.1.68 手动审核即时预览与紧凑协议：** 模型生成词源只需提交 replacement 或 segments，`confidence` 与 `evidence` 不再必填；词典选项仍须使用当前目标的合法 `choice_id` 且不得附带自造词源。手动审核部分结果通过时，合法结果立即以**可回退的预览**形式显示，不再等全部目标修复后才看到；重复／跨批／无效答案只影响相关目标。诊断会统计实际包含转换和无转换的决定，以及网页内容变化而不能写入的情况。注意：预览不是本批最终确认；模型生成的语义正确性仍需抽查。

**v1.1.69 唯一词典候选的语义风险修复：** 不再把本地候选的高匹配评分当成词义已经得到验证。对没有完整搭配或单位证据、且词典只有一条候选的双音节词，优先让模型审核词典释义；当实际语义缺失时，允许模型在已开启实验性生成词源的前提下提出字形，不再直接标注唯一同音词。此规则不绑定固定词汇或领域，保留多词典候选与已有完整搭配的快速路径。若模型审核关闭，风险词保留原文而非贸然转换。手动回复只要存在不合法目标，其他合法结果仍可先行预览（v1.1.68）。

**v1.1.70 整词优先与定向纠错：** 实验性 `GEN_SEGMENTS` 先识别完整词干、助词与固有词部分；完整汉字词干优先生成一个连续汉字段。孤立单音节仍拒绝，但错误会明确要求重审整个词。自动审核第二次请求只重试失败 ID 并附其校验原因；手动审核纠错提示词也带每个目标的 `repair_feedback`，不再仅提示检查偏移。不会凭单个汉字自动猜出剩余字形；无法判断应选 KEEP。输出 token 估算移除废弃的 confidence/evidence 字段，避免不必要的过度分批。

**v1.1.71 实验性分词安全回退与标注率审计：** 原始词典候选在整词合并时仍会保存，但不自动恢复汉字。整词审核得到 KEEP 或未解决时，独立词界可靠的原词典目标进入额外语义审核；只要存在词界不可靠的子词，就再次复核整个词，避免单音节/错误同音词误标。新增模型采纳/KEEP/非转换/生成片段统计，以及实际 DOM 标注、页面变更、跨节点外来语和过滤原因统计，附有限词例。修复 GEN_SEGMENTS 缓存带多余 replacement 导致重新校验失败；唯一原文子段可不填 start/end（重复子段仍必须填）；统一弹窗与内容脚本版本。额外安全补审可能增加模型调用量，字形合法不代表词源含义必然正确。

## 5. 遇到问题

- **标注按钮无反应：** 确认词典已成功导入、扩展已重新加载，并刷新网页重试。
- **更新后仍出现旧错误：** 在 `chrome://extensions` 中重新加载扩展，随后刷新原网页（旧标签页仍可能运行旧脚本）。
- **手动审核分批未完成：** 保持当前网页打开，逐批提交并校验 JSON；不要在任务完成前刷新页面。
